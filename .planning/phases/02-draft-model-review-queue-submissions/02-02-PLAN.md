<objective>
Find, live-verify and document Attleborough's event sources, and save parser fixtures for the best ones, so Phase 3 can build fetchers against real bytes. The agent does the first pass across the spec §14 categories with a polite probe ladder (robots → platform fingerprint → TEC REST/iCal → feeds with event dates → JSON-LD → server-rendered check → ToS), then the owner adds the local URLs only a resident would know (Facebook-only groups, word of mouth), and the agent verifies those too (D-13). The result is `docs/research/event-sources.md` with two lists (D-16) and redacted fixtures with manifests under `tests/Fixtures/sources/` (D-14), guarded by an automated personal-data scan.

Purpose: RES-01, RES-02, RES-03. Runs in the first wave alongside the draft/queue code (D-15). Phase 2 can't be signed off until this plan is done, because research gates Phase 3 (STATE blocker "[Phase 2→3]").
Output: the research doc, fixture directories with manifests, a fixtures README, and one Unit test.
</objective>

## Phase Goal

ROADMAP Phase 2 ends with "the local source inventory is verified and fixtures are saved" (success criterion 5). This plan owns that half; it touches no application code.

This plan owns only `docs/research/**`, `tests/Fixtures/sources/**` and `tests/Unit/Fixtures/**`. It must not touch `app/`, `database/`, `config/`, `routes/` or other tests. `tests/Fixtures/public/` and `tests/Fixtures/views/` already exist and are out of scope (and out of the scan).

## Live-network rules (read before any probe)

- **Live internet is required at execution time.** This machine sits behind a corporate security gateway that rewrites some fetches. When the gateway answers (its own 302/block page, TLS interception error), record "no observation (local gateway)" and re-probe from another network before classifying.
- User-Agent for every request: `WhatsOnAttleboroughResearch/0.1 (+mailto:hello@whatsonattleborough.co.uk)`. One request at a time, at least 5 seconds between requests to one host (`sleep 5`). Use `curl -sS -D - -A "$UA"`; save raw bodies with `-o` before any processing.
- Never bypass anything (prohibition below). Already observed on 2026-10-17: Breckland Council and TicketSource answer `HTTP/2 403` with `cf-mitigated: challenge` even on robots.txt; Eventbrite disallows `/rss/`, `/atom/`, `/events/rss/`, `/events/atom/`.
- Probes are curl + manual review logged in the doc. Do not add research tooling to `app/` (Phase 3 builds the real fetcher and robots policy).
