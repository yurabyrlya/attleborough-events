<objective>
Open the public front door. Organisers submit events through a plain Blade form at `/submit` (no Livewire, works without JavaScript); each valid submission becomes a `pending_review` draft through 02-01's `DraftWriter` and never touches the public calendar. The interim `/privacy` page explains what is collected and kept. Spam defence (honeypot, timing token, Turnstile) is 02-09; rate limiting is 02-10.

Purpose: SUB-01, SUB-02, SUB-03 with D-01, D-02, D-04, D-08.
Output: routes, controller, FormRequest, `DraftData::fromSubmission()`, three public pages, the progressive venue reveal, footer links, a shared test helper, and tests.
</objective>

## Phase Goal

Success criterion 1: the organiser completes the form (repeats field, consent linking to the privacy notice), sees "will be reviewed", the event stays off the site, missing date/venue creates nothing.

## Wave-2 file ownership (parallel with 02-03 and 02-04)

This plan owns its `files_modified`. It calls `DraftWriter::create()` only. Its tests must not use `EventDraftFactory` (02-03 creates it in the same wave) or assert the `Other` fallback (02-03's CategoryAssigner, same wave).

Use only the ten semantic colour tokens; every control carries `tap-target` (44px) and keeps the focus ring; visible labels (`text-sm text-muted`) above inputs (`tap-target w-full rounded-md border border-line bg-bg px-2 text-ink`, as in `events/partials/share.blade.php`); one filled primary button ("Send for review", `bg-accent text-accent-ink`); links stay underlined text; British English, friendly-noticeboard voice; h1 larger than h2; error text says what to do next and never relies on colour alone (visually hidden "Error:" prefix).
