# Phase 03 — Security

> Per-phase security contract: threat register, accepted risks, and audit trail.
> Register built from the `<threat_model>` blocks of plans 03-01 … 03-17 (46 threats T-03-01 … T-03-46 plus the reserved T-03-SC row) and every SUMMARY `## Threat Flags` section. Twelve summaries have one and all say "None" or point back to registered IDs. 03-01, 03-04, 03-08, 03-12 and 03-16 have no section. So there are no unregistered flags. Evidence was gathered at ASVS L1 (grep/read of code plus the enforcing tests) on commit 79fa61f. The gsd-security-auditor agent lacked the tools this needs, so a general-purpose agent gathered the evidence. One extra probe was run (`php -r` against sabre/vobject) to confirm the T-03-11 finding.

## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| Crawler → third-party sites | `HttpFetcher` GETs admin-configured feed URLs, every redirect hop and each host's robots.txt. Hostile DNS, redirects and huge bodies are expected | URL, honest User-Agent, conditional validators; response headers and bodies come back (untrusted) |
| Third-party feed bodies → parser/pipeline | `BodyValidator` → `IcsExtractor` (sabre/vobject) → `SourceItemRecorder` / `DuplicateDetector` / `MissingItemDetector` | ICS text, RRULEs, TZIDs, titles, descriptions, ORGANIZER (personal data), URLs (all untrusted) |
| Crawler → private storage | `RawBodyStore` writes gzip bodies to the private `local` disk | Raw response bytes, under paths built from integer ids |
| Admin browser → Filament Sources / Review / Rules | Single admin. Livewire state is client-controlled | Source URLs, title rules, per-source mappings, review decisions, reject reasons |
| Filament/Livewire → Publishing actions | `App\Publishing\Actions\*` and `SaveRules` re-check AdminGate, transitions and blockers on locked rows | Draft status, event/occurrence writes, event_sources links |
| Discovered drafts → public pages | Only approved drafts become events. Attribution comes from event_sources | Published facts, excerpt (contacts stripped), source names and http(s) links |

### Additional areas checked (no separate threat ID)

- **AdminGate on every `App\Publishing\Actions\*` class:** all 14 call `AdminGate::authorize` as the first statement of `__invoke`: ApplySourceUpdate 80, ApproveAllLikeThis 64, ApproveDraft 68, ChangeEventStatus 36, ChangeOccurrenceStatus 37, ConfirmSourceCancellation 67, IgnoreSourceChange 51, LinkEventSource 49, MarkDraftDuplicate 74, PublishEvent 45, RecordNotDuplicate 48, RejectDraft 43, ReopenDraft 46, UpdatePublishedEvent 62. Each has a non-admin test (RejectReopenDraftTest "refuses a non-admin reject or reopen and changes nothing", plus the tests listed above).
- **Livewire-forged reject reason:** ReviewActions::rejectReason (522-531) maps a forged `ignored` to null. RejectReason::rejectOptions() leaves out `ignored` (IgnoreSourceChangeTest "keeps "Ignored" out of the Reject dialog …"). No test submits a forged value directly; the evidence for the drop is the code itself.
- **Sources Pause action** writes `is_active`/`next_check_at` via forceFill (SourceActions 140) behind the gates described in T-03-41.

### Transferred to Phase 5 (production configuration)

No Phase 3 threat is formally transferred. Phase 5 deployment needs to keep these production halves intact:

- **T-03-16:** the systemd queue worker must not pass a `--timeout` below FetchSourceJob's 75 s, and DB_QUEUE_RETRY_AFTER must stay above 75 (currently 90).
- **T-03-09:** Caddy serves only `public/`, so `storage/app/private/ingest/raw` (raw third-party bodies) stays off the web.

### Non-blocking hardening observations (not registered threats)

- **SsrfGuard::isPublic** accepts the local-use NAT64 prefix `64:ff9b:1::/48` (RFC 8215), because FILTER_FLAG_GLOBAL_RANGE returns true for it. This is exploitable only if the host network has a local NAT64 translator; the Hetzner VPS does not. Optional fix: also block the `0064ff9b0001` prefix.
