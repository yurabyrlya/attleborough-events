<objective>
Give the admin status control over published events and their dates. On the Occurrences table that 01-04 made read-only, the admin can cancel, hide or restore one date. On the edit page, the admin can hide, show, cancel or reinstate the whole event. Every transition is a backed-enum `canTransitionTo()` rule enforced inside two new domain actions, `ChangeEventStatus` and `ChangeOccurrenceStatus`. These are the single choke point: admin-only, row-locked, writing audit columns `status_changed_at` / `status_changed_by`. Filament closures only call them. Hidden items disappear from the public list (01-08's event page reuses the same enum helper to 404). Cancelled items stay listed with the existing text "Cancelled" badge from 01-06 until they expire. Admin-set occurrence status survives `calendar:sync-occurrences` and edits. Nothing is hard deleted.

Purpose: completes ADM-03 (hide/unhide/cancel for events and individual occurrences; status survives regeneration; the edit half shipped in 01-04) and the status-driven half of CAL-07 (the badge appears because the admin cancelled something, and stays until expiry).
Output: status audit migration, enum transition rules, two domain actions, a Filament StatusActions factory wired into EditEvent and the Occurrences table, a status filter and no-delete guarantee on the events list, and end-to-end tests on PostgreSQL.
</objective>

## Flagged Assumptions

- **Transition matrix follows ARCHITECTURE Pattern 3 exactly.** No direct hidden↔cancelled moves. To hide a cancelled event, the admin reinstates it, then hides it. A direct move would let "Show on calendar" bring back an event without its "Cancelled" badge, or force the enum to remember a previous state. The cost is one extra click. Revisit if the owner finds it awkward.
- **Event status is independent of occurrence status.** Cancelling or hiding an event does not rewrite its occurrences. The public read combines the two (hidden wins, then cancelled shows one badge). Reinstating or showing the event therefore restores exactly what the admin had set per date.
- **Past occurrences can still change status** for the record. They have no public effect because the public list requires expires_at > now.
- **No cancellation reason field.** ADM-03 and spec §8.1 ask for a "Cancelled" badge only, so no free-text reason or public note is added. The audit columns record who changed what and when.
- **ADM-03 / CAL-07 edge rows:** all six CAL-07 categories (boundary, adjacency, empty, encoding, ordering, precision) were already lifted as truths in 01-06, and the ADM-03 adjacency / empty / ordering rows were lifted for the edit side in 01-04. This plan adds the status-side truths for the same ADM-03 categories (marked "(ADM-03 ..., status)" in must_haves) plus two backstops (lock-order concurrency and the 01-04 orphan rule). Nothing is dropped.
