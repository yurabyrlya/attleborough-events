<objective>
Align the existing test suite with the publish-DTO invariants that plan 01-12 adds (WR-02), before 01-12 lands, without deleting or weakening any test. Three tests depend on input the DTO will refuse and are rebuilt so they keep their intent; eight fixture files gain an organiser contact in their base data.

Purpose: split out of 01-12 (checker iteration 1: scope warning and blocker) so 01-12 stays within budget and every one of its must_have truths is reachable by its own tasks. The edits are valid on the current code, so this plan can run in wave 1 and leave the suite green; 01-12 (wave 2) then turns the invariants on.

The three rebuilds and why:
- PublishEventTest rollback test: it used a timed event with no start time to make EventTiming throw inside the transaction. After 01-12 the DTO refuses that at construction (outside the expect closure), so the test would error instead of proving rollback. That input case moves to 01-12's PublishableEventDataTest ("A timed event needs a start time."); this test keeps proving the transaction with a failure injected after save.
- EventSeoTest tagline fallback: blank descriptions will be refused by the DTO, but the page must still handle a stored blank description (importers and SQL do not go through the DTO). The event is published normally, then its stored description is blanked.
- EventPageContentTest "Listed by": an event with no attribution can no longer be published through PublishEvent, but the page's fallback still matters for stored rows. The event is built with the factory and makeOccurrence().

Output: three rebuilt tests, eight fixture files whose DTO bases all carry an organiser contact (organiserContact for constructor bases, organiser_contact for fromForm arrays), suite green on current code.
