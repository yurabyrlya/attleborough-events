<objective>
Let the admin publish and edit recurring series. In Filament the admin picks "Weekly on {day}", "Monthly on the {nth} {day}" or "Monthly on the last {day}" (options computed from the start date), with Ends = Never / On date (UNTIL) / After N times (COUNT). The rule is stored as an RRULE on the event, sabre/vobject 5 expands it in Europe/London over a rolling 90-day horizon, and occurrences are stored in UTC, upserted by recurrence_key (London Y-m-d) so that admin-set status is preserved, with rows the rule no longer yields pruned in the same transaction. Edits go through a new `UpdatePublishedEvent` action (the same choke point as `PublishEvent`), and a daily `calendar:sync-occurrences` command rolls the horizon forward. The public list shows one entry per occurrence.

Purpose: covers ADM-02 (manual entry with simple recurrence), the edit half of ADM-03 (the hide/unhide/cancel half is plan 01-05), CAL-08 (one entry per occurrence within 90 days), REC-01 (scheduled materialisation, upsert, status preserved) and REC-02 for recurring instances (all-day ends at local midnight on the 25-hour day, no end time means expiry 3h after start). It unblocks plan 01-05 (status actions on the edit page and occurrences table) and plan 01-09 (scheduler heartbeat beside this schedule entry).
Output: ManualRecurrence + RecurrenceExpander, recurring OccurrenceGenerator branch, UpdatePublishedEvent, Filament edit page + read-only Occurrences table, `calendar:sync-occurrences` + schedule, and DST-pinned tests.
</objective>
