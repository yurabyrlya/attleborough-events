<objective>
Ship the walking skeleton to production with zero-downtime releases. The first `dep deploy` from the laptop replaces the plan 01-02 probe with the plan 01-01 app at https://whatsonattleborough.co.uk. The owner then stores the CI deploy secrets in a branch-protected GitHub `production` environment and creates the single production admin interactively (ADM-01). From then on, every push to `main` that passes CI deploys itself. A curl loop running during a real CI deploy, and during a rollback drill, proves that visitors only ever get HTTP 200.

Purpose: this is the last third of the Walking Skeleton (`01-SKELETON.md`): admin creates a real event in prod → resident sees it on a phone → served by a release GitHub Actions deployed with zero downtime. It completes OPS-02 (HTTPS + supervised worker + cron from plan 01-02, plus zero-downtime deploys from GitHub Actions here) and ADM-01 in production. It applies D-02 (APP_URL on the canonical apex), D-04 (MAIL_FROM_ADDRESS hello@), D-01 (site name in APP_NAME / MAIL_FROM_NAME) and D-09 (`--no-dev`: Boost never on the server).
Output: `deploy.php`, `ops/complete-env.sh`, `ops/zero-downtime-check.sh`, the CI `deploy` job, the deploy/rollback runbook, a live production release and the production admin account.
</objective>
